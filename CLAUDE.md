## The project
*(Fill or update after asking the user's permission. Contains the project's background, motivation, goal(s) and approach. Keep entries short, one line each.)*

- lightview: a minimal image viewer for Linux, written fully in Rust, meant to be the user's default image app (Windows later).
- Motivation: an image viewer that opens instantly and feels snappy, with no bloat.
- Goals: first image on screen in under 100 ms (12 MP JPEG, cold start); instant next/prev; v1 is view only.
- Approach: egui/eframe (OpenGL) + the `image` crate, decoding on a background thread, neighbouring images decoded ahead; full spec in `docs/PROJECT_BRIEF.md`.

## Principles (do not remove or weaken these)
1. **Think Before Coding** — surface assumptions, ambiguity, and simpler alternatives before writing anything; stop and ask if something's unclear.
2. **Simplicity First** — write the minimum code the problem needs, no speculative features or unrequested flexibility.
3. **Surgical Changes** — touch only what the task requires; don't refactor, "improve," or clean up unrelated code.
4. **Goal-Driven Execution** — turn tasks into verifiable success criteria (usually tests) and loop until they pass, rather than stopping at "looks right."

## Project Notes
*(Project-specific facts Claude has learned go here — commands, gotchas, conventions. Keep entries short, one line each.)*

- Scope and targets live in `docs/PROJECT_BRIEF.md`; read it first.
- Dev machine: Kubuntu, KDE Plasma on Wayland, i7-8750H with turbo OFF (`intel_pstate/no_turbo=1`), so timings are pessimistic.
- Build/test: `cargo test`, `cargo build --release`. `--timings` prints window/preview/full/navigation ms; `--bench` does the same and quits after the first full image.
- Modules: `main.rs` startup, `app.rs` state + `ui()` steps (`app/`: `menu.rs` actions/shortcuts/menus, `input.rs` input + action dispatch, `canvas.rs` texture + painting, `dialogs.rs`, `ai_tools.rs`), `load.rs` decode pool + EXIF + folder listing, `view.rs` zoom/pan math, `edit.rs` the edit state (`Doc`: crop → transform → size → colour) and `render` for saving, `curves.rs` tone curves and the Adjust Curves panel, `inspector.rs` the sidebar (EXIF sections in `exif_edit.rs`), `svg.rs` SVG parse/render, `markup.rs` markup elements: egui painting, tiny-skia/ab_glyph flattening, toolbar.
- Install / set as default viewer: `./install.sh` (binary → `~/.local/bin`, desktop file → `~/.local/share/applications`, `xdg-mime default`).
- Package: `./package-deb.sh` writes `lightview_<version>_amd64.deb`; pushing a `v*` tag matching `Cargo.toml` makes `.github/workflows/build.yml` build it on ubuntu-22.04 (glibc 2.35 floor), plus the Windows `.msi`, and publish one release. `xdg-mime` prints a harmless `qtpaths: not found` here. Discover's preview of a local `.deb` shows name `lightview_0` (file name up to the first dot) and licence Unknown (PackageKit's apt backend hardcodes it): not a packaging bug.
- Translations: wrap new UI text in `tr`/`trf` (`tr_key` inside `const` tables, shown through `tr`) and add a line to all five `locales/*.tsv`; a test fails until they match. `--bench` saves settings on exit, so use a throwaway `XDG_DATA_HOME` when testing languages.
- Disk: `target/` grows without limit (21 GB seen, 18 GB of it `target/debug`) because each change leaves a ~0.4 GB test binary; `cargo clean` is safe.
- Saved data: eframe persistence in `~/.local/share/lightview/app.ron` (keys `recent`, `settings` and `toolbar`, the drawing toolbar shown/hidden). `settings::load()` reads that file directly in `main`, so the saved window size applies before the window exists. Keep `persist_window: false` and `persist_egui_memory() = false`, so the window always opens at 1280×720.
- little_exif gotchas: it panics on unexpected input (wrap with `catch_unwind`), returns *empty* metadata when it can't decode (writing that back wipes EXIF), trims the NUL padding off fixed-size strings (harmless), loops for ever on a looping IFD chain (`exif_edit::ifd_chains_end` checks first), and takes the first APP1 anywhere, even behind the image data, with `Exif` optional.
- usvg opens any `href` path even with `resources_dir` unset, and inflates gzip with no limit; `svg::load` turns both off. `GifDecoder::new`/`WebPDecoder::new` skip the `image` crate's limits (`ImageReader` applies them). Neighbours are decoded unopened, so anything in `load` runs on files the user never chose.
- Security checks: `cargo install cargo-audit --locked --root <scratch>`, then `<scratch>/bin/cargo-audit audit`; reasoned exceptions live in `.cargo/audit.toml`. Run memory attacks as `(ulimit -v 4000000; timeout 60 <test binary> --exact <test>)`; the cap hides `fs::read`'s runaway growth (`try_reserve` fails cleanly), so don't read a pass there as safe.
- `--bench` never quits when the first image fails to decode: a timeout there says nothing about decode time. A worktree with a shared `CARGO_TARGET_DIR` overwrites the same test binary, so rebuild before trusting it.
- Screenshots: `spectacle -b -n -a` captures the *active* window, and KDE often doesn't focus lightview, so it can capture the user's other windows. Don't use it for checks.
- Resize opaque images as RGB (U8x3), not RGBA: 9 ms vs 66 ms for 12 MP → 480×360.
- libjpeg-turbo is loaded at run time from `libturbojpeg.so.0` (`src/turbo.rs`, via `libloading`); no `-dev` package needed. `--bench` prints every preview drawn with its size (EXIF thumbnail, then the reduced-size decode).
- `--bench` window times vary 110–230 ms run to run; compare binaries by interleaving runs, and compare image times against each run's own window time.
- Clipboard: eframe's `clipboard` feature (arboard + Wayland data-control); Ctrl+C/X/V arrive as `Event::Copy/Cut/Paste(Image)`, not key presses. A copied image lives only while lightview runs. Cross-process check: `cargo test clipboard_copy -- --ignored &` then `cargo test clipboard_paste -- --ignored`.
- AI: no build feature; `ort` loads ONNX Runtime at run time from `~/.local/share/lightview/lib/libonnxruntime.so.1.31.1` (installed by Tools → Download AI Runtime…, or `cargo test install_runtime -- --ignored`). Models: any `*.onnx` in `~/.local/share/lightview/models` (on the dev machine: BSRGAN plus the five `lightview-models` conversions). Catalog, presets and choice logic in `ai.rs`; choice and per-file preprocessing in `Settings.ai`. Downloads are pinned by SHA-256 in `ai.rs`; updating `ort` means updating the runtime URL and checksum. Check: `LIGHTVIEW_AI=photo.jpg [LIGHTVIEW_AI_MODEL=<file>] cargo test --release remove_background -- --ignored --nocapture`.
- Denoise/Enhance timing check: `LIGHTVIEW_AI=crop.png LIGHTVIEW_AI_MODEL=<file or path> cargo test --release restore_photo -- --ignored --nocapture`. SCUNet ≈ 57 s/MP here with 512 px tiles (6 intra-op threads beat 12); SwinIR only takes 128 px tiles, ≈ 4× slower.
- GPU: installed on the dev machine in `~/.local/share/lightview/gpu` (`cargo test install_gpu -- --ignored`). Check: `LIGHTVIEW_AI=crop.png LIGHTVIEW_AI_MODEL=<file> cargo test --release gpu_restore -- --ignored --nocapture` (GPU vs CPU result and timing); `CUDA_VISIBLE_DEVICES=""` forces the fall-back. `/tmp` is a 7.8 GB tmpfs: keep big downloads out of the scratchpad.
- Remove Object check: `LIGHTVIEW_AI=photo.png LIGHTVIEW_AI_MODEL=lama_fp32.onnx [LIGHTVIEW_AI_BOX=x,y,w,h] cargo test --release inpaint_photo -- --ignored --nocapture`. LaMa loads in ~18 s at any ONNX Runtime optimisation level and fills in ~1 s on the GPU, ~3.5 s on the CPU.
- Model conversions live in `../lightview-models` (own git repo). Python here is 3.14 only; PyTorch 2.5.1 needs a conda 3.12 env (`conda create -p <scratch>/env python=3.12`). Python's urllib can hang on this machine; use curl for downloads.
- Windows: `cargo check --target x86_64-pc-windows-gnu` / `cargo build --release --target x86_64-pc-windows-gnu` (mingw-w64 is installed) gives a test `.exe`; the dev laptop dual-boots Windows 11. Release packages come from GitHub Actions (MSVC build, WiX v5 `.msi`, static CRT).
- Windows gotchas: `canonicalize` gives `\\?\C:\…` paths, so never compare them with paths from the OS directly (`load::restore_trashed`); the default-viewer prompt and button stay hidden there because `desktop_installed()` is false (the `.msi` registers the app); `trash` needs a `coinit_*` feature to compile with default features off; its Windows `TrashItem.name` is suspected to lose the extension when Explorer hides extensions (`load::is_trashed_copy` uses `id`'s; fix awaiting a Windows retest).
- Windows checks from Linux: `CARGO_TARGET_X86_64_PC_WINDOWS_GNU_RUNNER=wine cargo test --target x86_64-pc-windows-gnu` (expect the 2 download tests, `text_is_drawn` and `trash_round_trip` to fail: Wine has no PowerShell, no fonts here and no Recycle Bin call). Local test `.msi`: WiX v5 is Windows-only, so use `wixl` (`mamba create -p <scratch>/env -c conda-forge msitools powershell`; `pwsh` also runs the `platform.rs` scripts, as PS 7 rather than Windows' 5.1) on a WiX v3-schema copy of `packaging/windows/lightview.wxs`, with `turbojpeg.dll` fetched as in `build.yml`; install-test with `wine msiexec /i x.msi /qn` in a throwaway `WINEPREFIX`.
- WiX: each versioned file (exe, dll) in `lightview.wxs` needs its own `Component` (WIX0368 with automatic GUIDs); only real WiX on Windows reports it, so CI is the check.
- fontdb's generic families are Windows fonts and usvg silently drops text with no font, so `svg.rs` picks them from what's installed; `resvg` brings a second tiny-skia (0.12), so use its re-export.
- Metadata checks: exiftool isn't installed (running a downloaded copy is blocked); compare with `python3 -I` + PIL 12.3 and `LIGHTVIEW_INSPECT=photo.jpg cargo test print_inspector -- --ignored --nocapture`.
- Per-pixel loops: `f32::round` is a library call on baseline x86-64 (it took about half of the HSL curves' time); use `(v + 0.5) as u8`, whose cast also clamps. The i18n test only scans source above a file's first `#[cfg(test)]`, so keep test helpers below all `tr` calls.
- SVG to PNG: `ksvgtopng <w> <h> in.svg out.png` (no inkscape/rsvg here); it's Qt SVG Tiny, so no filters, masks or `clipPath`. `icon/aperture.svg` is the app icon, installed as `lightview.svg`; after changing it, re-render `icon/lightview-256.png` (embedded for X11): `ksvgtopng 256 256 icon/aperture.svg icon/lightview-256.png`, and `icon/lightview.ico` (embedded in the `.exe` by `build.rs`; 16–256 px PNGs combined with PIL).
- Headless egui tests: `Context::run_ui` with `RawInput`; call `output.textures_delta.clear()` each frame or it panics on drop. Pointer state needs a few frames (`modal_blocks_image_hover` in `app/dialogs.rs`). A real `App` builds in tests with `CreationContext::_new_kittest` (`app_with_image` in `app.rs`), so `handle(Msg)` is testable.
- egui right panels: content wider than the panel's max moves its left edge right, over the content, so keep sidebar content wrapping; `Grid` cells and `ui.horizontal` don't wrap by default (`Label::wrap()`, `horizontal_wrapped`).
- tiny-skia strokes width 0 as a hairline, egui draws nothing: guard in `markup::flatten` or the saved file differs from the screen.
- M1 result (2026-10-28): eframe alone takes 115–200 ms to the first frame; a 12 MP JPEG takes ~360–410 ms to decode in a fresh process (~190 ms warm) → P1 is ~420 ms, so the 100 ms target is missed.

## Architecture Decisions
*(Log of important architecture/approach discussions with the programmer. One line per decision: what was decided and why, not the full discussion.)*

Format: `YYYY-MM-DD — decision — reason`

- 2026-10-28 — UI with egui/eframe — needs menus/dialogs and a future Windows port.
- 2026-10-28 — decoding with the `image` crate: png/jpeg/gif/webp/bmp, plus tiff (first page) since 2026-10-30 and ico (largest size, view only) since 2026-10-31 — fully Rust, no C dependencies.
- 2026-10-28 — no AVIF/HEIC/RAW, gallery, delete/move or packaging in v1 — keep the app simple.
- 2026-10-28 — UI always renders with eframe's OpenGL backend (glow); a "GPU image scaling" setting (off by default) picks GPU vs CPU (`fast_image_resize`) scaling — egui has no CPU-only renderer.
- 2026-10-28 — v1 is view only: rotate/flip never change the file; Save As/Export later, Draw/EXIF editing a later phase — keep v1 small.
- 2026-10-28 — fixed default window (480×360, now 1280×720, changed 2026-10-28), never resized on navigation or remembered; fit-to-window (aspect kept, small images upscaled) on black; no wrap; sort order setting (name default) — user's choice, kept as behaviours not settings.
- 2026-10-28 — keep egui after M1 missed 100 ms; split P1 into P1a (window <200 ms) and P1b (image as fast as decode allows), and show the EXIF preview first in M2 — decoding, not egui, is the bottleneck.
- 2026-10-28 — M2: apply EXIF orientation (phone photos are often rotated); hand-written bounds-checked EXIF thumbnail reader instead of an EXIF crate; 3-thread decode pool with a replaceable wanted list; menus moved to M3.
- 2026-10-28 — M3: File → Close closes the window (Ctrl+W); Info = name/folder/dimensions/size/type; menus hidden in fullscreen; Open Recent lists only explicit opens; file dialog via `rfd` (XDG portal, pure Rust), run on its own thread.
- 2026-10-28 — M4: rotate/flip is a `view::Transform` applied to the small resized output (not the decoded image), so it's cheap and zoom/pan work in rotated coordinates; it resets on image change and resets zoom to Fit.
- 2026-10-28 — M5: GPU scaling uploads the whole frame once (mipmaps for Bilinear) and draws a mesh whose UVs carry the rotate/flip; images over `max_texture_side` stay on the CPU path. With GPU on, Bicubic/Lanczos3 fall back to Bilinear. Date sort is oldest first.
- 2026-10-28 — M6 (user's choices): one Save As (format by extension, no Export); overwrite allowed after the system dialog's confirmation; JPEG quality fixed at 90; EXIF kept with orientation reset + thumbnail unlinked; atomic write via temp file + rename; animated images not saveable yet.
- 2026-10-29 — M7 EXIF editing (user's choices): Tools menu; `little_exif` (pure Rust) rewrites only the JPEG's EXIF block; JPEG only; always a copy, never the original; MakerNote dropped; little_exif calls wrapped in catch_unwind, refuse when it reads existing EXIF as empty, and verify the written buffer before writing it.

- 2026-10-29 — JPEGs: reduced-size decode (largest of 1/8, 1/4, 1/2 that still covers the fitted viewport, after EXIF orientation) sent as a `Msg::Preview`, with 1:1 decoded in parallel in the same scope; both via libjpeg-turbo when installed, otherwise unchanged pure-Rust path — decoding was the bottleneck; the pure-Rust scaled decode only saved ~12%, so it isn't used.
- 2026-10-29 — v2 build choices: edits are one `Doc` (crop → rotate/flip → size → colour → markup) with snapshot undo; colour runs on the cached resized pixels; markup is in output px and flattened with tiny-skia + egui's own font; erase = transparent when the image has alpha, else background colour; clipboard via eframe's `clipboard` feature; AI models (rembg's silueta / isnet) downloaded with the system curl — reuse what's already in the tree, no extra HTTP crate.
- 2026-10-29 — M16 (user's choice): one lean binary for everyone; ONNX Runtime is downloaded on request (separate menu item, no one-click bundle) and loaded with `ort`'s load-dynamic on first use; all downloads checked against pinned SHA-256 — ship a single executable without the 16 MB runtime.
- 2026-10-29 — M17 (user's choices): Tools → AI Models… dialog; 7-model rembg catalog pinned by SHA-256; unknown models auto-detect input size with editable per-file preprocessing; one model (drop-down, saved as a setting) for both Remove Background and Remove Background and Crop, which only adds the crop — custom models without code changes.
- 2026-10-29 — AI downloads (models and runtime) show the upstream licence, embedded from `licenses/`, and start only after Accept; asked every time — the user must agree to third-party terms before fetching them.
- 2026-10-29 — M18 (user's choices): Denoise = SCUNet real-PSNR (blind noise + JPEG, no setting), Enhance = SCUNet real-GAN; SUPIR dropped (non-commercial, GPU), BSRGAN dropped (4× only); third-party ONNX conversions (Heliosoph) pinned by revision + SHA-256; CPU is ~57 s/MP, so preview a ≤256 px patch of the visible area first (≈ 5 s), then apply to whole image/selection with progress + Cancel.
- 2026-10-29 — M19 (user's choice): optional NVIDIA GPU support (ORT CUDA 12 build + NVIDIA PyPI libs, ~1.5 GB, pinned) because it's ~10× faster on the GTX 1050; CUDA 12 not 13 (13 drops Pascal); the CUDA libs are dlopen'ed first because the CUDA provider has no RUNPATH; CPU fallback with the reason shown.
- 2026-10-29 — Enhance = BSRGAN 4× (user's choice): third-party fp16 ONNX (FuryTMP) since no trusted conversion exists; SCUNet GAN removed; results 4× bigger for now; upscalers use 256 px tiles (4 GB GPU) and tile outputs are written without blending (memory).
- 2026-10-29 — DarkIR (user's choices): converted ourselves in a separate repo `lightview-models`, offered under Enhance; models now carry `max_tile` (DarkIR 1024: its FFT block is global per tile) and their own first-use notice.
- 2026-10-29 — v2 roadmap (`docs/ROADMAP-v2.md`, user's choices): edits as an undoable edit list applied only when saving a copy; AI tools last, behind an optional `ai` cargo feature; no JPEG 2000 (no pure-Rust encoder), TIFF added; selection = rectangle/ellipse/lasso, no smart lasso; rotate/flip now saved; GIF export added; ask before dropping unsaved edits; paste = movable element so Selection follows Draw; arboard/tiny-skia/ab_glyph/ort approved — keep the original safe and the default build small.
- 2026-10-30 — `lightview-models` publishes no ONNX files (user's choice): Real-ESRGAN and DarkIR stay out of `CATALOG`; users convert them and copy them into the models folder, and lightview recognises them by file name (`SELF_CONVERTED`) for task, tile size and notice — no release to depend on.
- 2026-10-30 — a shrunk image is shown from a cached frame resized to its output size (`edit::bake`, Lanczos3 as on save), fed into the normal draw path; enlarging stays on the decoded pixels — the view must match the saved file, and baking big upscales would cost memory.
- 2026-10-30 — GPL-3.0-or-later (user's choice; all 217 crates are compatible); crate and font notices are generated into the .deb by `third-party-notices.py` at package time so they can't go stale; no .deb signature, since nothing checks one outside an apt repository and the install warning is accepted.
- 2026-10-30 — M20 (user's choices): six languages via English-text keys in `locales/*.tsv`, no i18n crate; one global language so `tr` works on any thread and `&'static str` signatures stay; first launch follows the system (pt_BR maps to pt-PT) and fixes the choice in Settings; licences stay English.
- 2026-10-30 — UI fonts are Roboto + Droid Sans Mono (Apache-2.0) + emoji-icon-font (MIT) from `fonts/`, with eframe's `default_fonts` off — egui's Ubuntu and OFL fonts aren't clearly GPL-compatible; Roboto has no `→`, so UI labels avoid it.
- 2026-10-30 — distribution (user's choices): a .deb built with plain `dpkg-deb` by GitHub Actions, no custom wizard (downloaded binaries aren't executable, so a wizard would fail at step one); Debian family only; default viewer asked at first launch and in Settings, because a package runs as root and defaults are per user — simplest flow for a Windows newcomer.
- 2026-10-29 — menus File · Edit · View · Image · Tools, each action once (no Export submenu, Crop = crop to selection when there is one, Settings in Edit with Ctrl+,, no Draw menu) — the menus built from the draft repeated features.
- 2026-10-30 — version and a "Check for updates" button (opens the Releases page) sit at the bottom of Settings: no sixth menu and no automatic update check; AppStream metainfo ships in the .deb only.
- 2026-10-30 — deleting an image always asks first and moves it to the system Trash with the `trash` crate (no permanent delete); Ctrl+Z undoes edits first, then restores the last deleted image, for that session; Delete still means element/selection first — recoverable, works on other drives, and the crate covers the Windows port.
- 2026-10-30 — `app.rs` split into child modules `src/app/*.rs`, not sibling files — only children see `App`'s private fields; `App` stays one flat struct, no sub-structs, no dialog trait.
- 2026-10-30 — app icon = aperture in kingfisher colours (user's choice): one SVG in hicolor/scalable via `Icon=lightview`, plus an embedded 256 px PNG for X11 — on Wayland the panel finds it through the app id and `.desktop` file, and winit ignores window icons.
- 2026-10-30 — Windows downloads and unzips use PowerShell (`platform::download`/`unzip`), Linux keeps curl/tar/unzip — a real Windows 11 PC had no curl.exe; no HTTP crate.
- 2026-10-29 — M21 Windows (user's choices): one code base with per-OS bits in `platform.rs`/`ai.rs`; releases (Linux .deb + Windows .msi into Program Files) built by GitHub Actions; ship `turbojpeg.dll` since it's < 5 MB; developed on `main` since 2026-10-31.
- 2026-10-31 — Auto Levels is a button that sets the Exposure and Contrast sliders (user's choice); `Adjust.levels` removed, so one stretch for all channels and no colour-cast correction — every adjustment stays visible and editable. Save As lists the source's format first, since rfd has no current-filter option and dialogs start on the first filter.
- 2026-10-31 — Remove Object (user's choices): LaMa for quality and MI-GAN for speed, catalog only because each has its own tensor layout; runs on a square of context around the selection, with no preview since Ctrl+Z undoes it; the session stays loaded between runs (LaMa takes ~18 s to load) and is dropped before any other model loads, so a 4 GB GPU isn't held.
- 2026-10-31 — right-drag pans with any tool and in the before/after preview; left-drag still pans with no tool (user's choice); the button that started a drag owns it (`App::right_pan`), because egui's `dragged`/`drag_started`/`drag_stopped` fire for every button.
- 2026-10-31 — markup shows at image resolution from the start (user's choice), so low-res images look as saved: `draw` shows `edit::flat` (the save path) as the frame and egui paints only handles and the text being typed; elements stay editable. On the UI thread, so up to 16 MP (the single frontier, user's choice), and only once a change ends: drags, typing and Adjust Color stay at screen resolution, because rendering every frame lagged at 1600×900; above 16 MP and on animations, markup always stays at screen resolution.
- 2026-10-31 — UI font size (Settings, 10–20, default 13 = egui's body size) scales all text styles from egui's defaults, text only rather than `zoom_factor`, which would also scale icons and panels; bubbles use Body so they follow it.
- 2026-10-31 — SVG via `resvg` (user's choices): `frames[0]` stays the 1× render that edits, Save, Copy and AI use; a display-only render (next power of 4 at or above the zoom, 64 MP cap, whole image) swaps in inside `draw`, so coordinates never change; markup/shrinking stay at 1× (view = saved); no SVG writing, Save As defaults to PNG; listed under Open With but not claimed by set-as-default.
- 2026-10-31 — Adjust Curves (user's choices): separate panel with an RGB/HSL/HSV dropdown; RGB curves join `Adjust`'s LUTs, HSL/HSV convert per pixel; only the selected space applies and Done drops the others', so no hidden edits; shares `adjusting` with Adjust Color, so Done/Cancel covers both; `Curve` is a fixed array so `Adjust` stays `Copy`.
- 2026-10-31 — `third-party-notices.py <target>` prints every licence, so the `.deb` and `.msi` carry the same text and can't drift; `release` needs only Linux to succeed, so Windows (experimental) can't block a release and re-running its job adds the `.msi`.
- 2026-11-01 — security audit (user's choices): opening a file, or sitting next to one, must do no harm. `load` reads only regular files up to 1 GiB; animations stop at 1 GiB of frames and keep what fits; SVGs use embedded images only and gzip is refused; the Windows `turbojpeg.dll` loads only from the exe's folder; Save As erases the old EXIF thumbnail bytes (a MakerNote preview survives); Remove Location also drops XMP segments naming GPS; Save As keeping GPS stays (M6). No sandbox or separate decode process (big change, startup cost), so libjpeg-turbo stays the native risk; the default worker stack is enough at usvg's depth limit.
- 2026-10-31 — no Linux tarball (user's choice): releases are the `.deb` and `.msi` only; other distributions build from source with `install.sh`, which now always builds.
